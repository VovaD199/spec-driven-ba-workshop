> ЗАПАСНИЙ ПРИКЛАД для дня 3 (поточна гіпотеза, RULE/AC з Дня 2). Обидві зміни справді застосовано на шаблоні lf-client і перевірено командою `npx jest …` (Linux, Node 22). **У браузері й у режимі `npm run dev` нічого не перевіряли**: це записано нижче в «Не доведено». Читайте, повторіть проби самі й додайте власні спостереження (див. `fallback/uk/README.md`). Зміни коду в PR не потрапляють, лише цей документ.

## 1. Гіпотеза

*«Якщо зробити телефон обов'язковим і зменшити мінімальну довжину повідомлення, система поводитиметься узгоджено на клієнті й сервері.»* (RULE-03, RULE-04, AC-01, AC-02.)

## 2. Налаштування пісочниці

Гілка `poc/day-3` від `main` (або тимчасові зміни, скасовані через `git restore .`). Документи спершу закомічено, код потім скасовано, у `main` нічого не потрапило.

## 3. Зроблені зміни

1. **Проба 1 (телефон):** на сервері в `app/lib/utils/validateContactData.ts` перевірку телефону зроблено безумовною (замість `if (phoneNumber)`); у `ContactForm.tsx` прибрано `.optional()` зі схеми телефону.
2. **Проба 2 (довжина повідомлення):** `MESSAGE_MIN_LENGTH` у `app/constants/validation.ts` змінено з 10 на 5. Число `.min(10, …)` у `ContactForm.tsx` і текст помилки в `i18n/messages` **не чіпали**: так видно розбіжність.

## 4. Докази

- **Проба 1, тести:** `npx jest app/lib/utils/validateContactData.test.ts --coverage=false`. До зміни 14 із 14 зелених. Після зміни **1 червоний**: `should return no errors for valid input` (вхідні дані тесту не містять телефону, тож тепер сервер повертає помилку). Решта 13 зелених.
- **Проба 1, висновок:** старий тест кодує правило «телефон необов'язковий» (RULE-03). Червоний тест це не поломка, а доказ того, що правило змінюється і тест треба оновити разом із вимогою (AC-01).
- **Проба 2, тести:** `npx jest app/lib/utils --coverage=false`. Після зміни **1 червоний**: `should return error if message is too short` (у ньому повідомлення «Too short», 9 символів, тепер валідне), 194 тести зелених.
- **Проба 2, дублювання правила (за кодом):** довжина повідомлення записана щонайменше в трьох місцях: константа `MESSAGE_MIN_LENGTH`, число `.min(10` у `ContactForm.tsx`, текст помилки в `i18n/messages` (`en` і `uk`). Зміна лише константи залишає форму й сервер із різними правилами.

## 5. Чекліст валідації

**Доведено (результат тестів, який я бачив сам):**
- Старий тест `should return no errors for valid input` червоніє, коли телефон на сервері стає обов'язковим.
- Старий тест `should return error if message is too short` червоніє, коли мінімум стає 5.

**Не доведено:**
- Що показує форма в браузері без телефону (є помилка й позначка «обов'язкове»?): браузер не відкривали.
- Що форма в браузері приймає чи відхиляє повідомлення з 6 символів (за кодом вона й далі вимагає 10).
- Що `/api/collaboration`, який справді викликає сторінка «Контакти», поводиться так само.
- Що `GetNotesModal` потребує того ж правила (Q-04).

**Потрібен розробник:**
- Чи не ламає обов'язковий телефон існуючі звернення й інтеграції.
- Чому клієнт і сервер мають різні числа замість спільної константи.
- Який мінімум довжини правильний (питання до замовника).

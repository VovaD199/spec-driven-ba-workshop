# Глосарій базових термінів

Скорочений довідник. Кожне поняття має офіційне джерело для докладнішого читання.

| Термін | Простими словами | Де читати |
|---|---|---|
| Репозиторій | Папка проєкту з історією змін | https://docs.github.com/en/repositories |
| Клон (clone) | Копія репозиторію на вашому комп'ютері | https://docs.github.com/en/repositories/creating-and-managing-repositories/cloning-a-repository |
| Гілка (branch) | Окрема лінія змін, щоб не псувати основну | https://docs.github.com/en/pull-requests/collaborating-with-pull-requests/proposing-changes-to-your-work-with-pull-requests/about-branches |
| Коміт (commit) | Збережений знімок змін з коментарем | https://git-scm.com/book/en/v2/Git-Basics-Recording-Changes-to-the-Repository |
| Push | Відправка комітів на GitHub | https://docs.github.com/en/get-started/using-git/pushing-commits-to-a-remote-repository |
| Pull Request (PR) | Пропозиція влити зміни з гілки в основну, з обговоренням | https://docs.github.com/en/pull-requests |
| diff | Різниця між двома версіями файлу | https://git-scm.com/docs/git-diff |
| Термінал | Вікно, куди вводять текстові команди | https://developer.mozilla.org/en-US/docs/Learn_web_development/Getting_started/Environment_setup/Command_line |
| Node.js / npm | Середовище виконання JavaScript / менеджер пакетів | https://nodejs.org |
| localhost:3000 | Адреса вашого застосунку на вашому ж комп'ютері | https://developer.mozilla.org/en-US/docs/Learn_web_development/Howto/Web_mechanics/What_is_a_web_server |
| API | Спосіб, яким програми обмінюються даними | https://developer.mozilla.org/en-US/docs/Glossary/API |
| Markdown | Простий текстовий формат із заголовками й списками | https://www.markdownguide.org/basic-syntax/ |
| Mermaid | Малювання діаграм текстом у Markdown | https://mermaid.js.org |
| AI-агент (Cursor) | AI, що читає файли й вносить зміни за вашим запитом | https://docs.cursor.com |
| MCP | Протокол підключення AI до зовнішніх сервісів | https://modelcontextprotocol.io |
| Специфікація (spec) | Письмовий опис, що саме має робити система | День 1 |
| AC (acceptance criteria) | Критерії приймання: коли вимога виконана | День 2 |
| NFR | Нефункціональні вимоги: швидкість, безпека, приватність | День 2 |
| PoC / MVP | Доказ ідеї / мінімально життєздатний продукт | День 3 |
| PAT | Особистий токен доступу, замінює пароль у деяких інтеграціях | https://docs.github.com/en/authentication/keeping-your-account-and-data-secure/managing-your-personal-access-tokens |

*Глосарій розширюється разом із днями.*

# Glossary of basic terms

| Term | In plain words | Read more |
|---|---|---|
| Repository | Project folder with change history | https://docs.github.com/en/repositories |
| Clone | A copy of a repository on your computer | https://docs.github.com/en/repositories/creating-and-managing-repositories/cloning-a-repository |
| Branch | A separate line of changes that keeps main safe | https://docs.github.com/en/pull-requests/collaborating-with-pull-requests/proposing-changes-to-your-work-with-pull-requests/about-branches |
| Commit | A saved snapshot of changes with a message | https://git-scm.com/book/en/v2/Git-Basics-Recording-Changes-to-the-Repository |
| Push | Sending commits to GitHub | https://docs.github.com/en/get-started/using-git/pushing-commits-to-a-remote-repository |
| Pull Request (PR) | A proposal to merge a branch into main, with discussion | https://docs.github.com/en/pull-requests |
| diff | Difference between two versions of a file | https://git-scm.com/docs/git-diff |
| Terminal | A window where you type text commands | https://developer.mozilla.org/en-US/docs/Learn_web_development/Getting_started/Environment_setup/Command_line |
| Node.js / npm | JavaScript runtime / package manager | https://nodejs.org |
| localhost:3000 | Address of your app on your own computer | https://developer.mozilla.org/en-US/docs/Learn_web_development/Howto/Web_mechanics/What_is_a_web_server |
| API | How programs exchange data | https://developer.mozilla.org/en-US/docs/Glossary/API |
| Markdown | Plain-text format with headings and lists | https://www.markdownguide.org/basic-syntax/ |
| Mermaid | Diagrams drawn as text in Markdown | https://mermaid.js.org |
| AI agent (Cursor) | AI that reads files and makes changes on request | https://docs.cursor.com |
| MCP | Protocol that connects AI to external services | https://modelcontextprotocol.io |
| Specification (spec) | Written description of what the system must do | Day 1 |
| AC (acceptance criteria) | Conditions under which a requirement is done | Day 2 |
| NFR | Non-functional requirements: speed, security, privacy | Day 2 |
| PoC / MVP | Proof of concept / minimum viable product | Day 3 |
| PAT | Personal access token, replaces a password in some integrations | https://docs.github.com/en/authentication/keeping-your-account-and-data-secure/managing-your-personal-access-tokens |

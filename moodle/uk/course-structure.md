# Структура курсу в Moodle

> ЧЕРНЕТКА v2. Описує, **що і куди** розмістити. Платформа: Moodle 5.2.3, додаткові плагіни не потрібні, відстеження виконання й чекліст не використовуються. Правила зарахування вже є на платформі (сторінка «Rules»). Англійська версія: [`../en/course-structure.md`](../en/course-structure.md). Завантаження в Moodle **не перевірялося** (потрібен курс-пісочниця).

## Принципи

- Один розділ на кожен день + вступний і довідковий розділи.
- Усе для проходження дня в одному місці: інструкція, завдання.
- Той, хто пропустив заняття, може пройти день самостійно за інструкцією.
- Матеріали ментора **не** публікуються учасникам.
- Джерело правди: Markdown у Git. PDF генерує `tools/build_materials.py`, у Moodle їх не правте вручну.

## Як зібрати файли для Moodle

```bash
pip install markdown
python3 tools/build_materials.py --all --pdf        # версія для учасників, uk і en
```
Результат у `build/`: `day-N-instruction.uk.pdf`, `…en.pdf`, а також Day 0, посібники встановлення, `github-mcp-setup`, `figma-mcp-setup`, `glossary`. Ментор отримує окрему збірку з `--teacher` (у Moodle не завантажувати).

## Загальна структура

| Розділ | Для кого | Вміст | Джерело в репозиторії |
|---|---|---|---|
| 0. Старт | Учасники | Про курс, розклад, канал підтримки | текст пише куратор |
| 0.1 Підготовка (День 0) | Учасники | Інструкція День 0, посібник встановлення, поради щодо моделей Cursor, словник, завдання «надішліть скріншот `git --version` і `node -v`» | `materials/uk/day-0/`, `materials/uk/setup/` |
| День 1 | Учасники | Мета, інструкція, здача | `materials/uk/day-1/` |
| День 2 | Учасники | Мета, інструкція, налаштування GitHub MCP (необов'язково), здача | `materials/uk/day-2/` |
| День 3 | Учасники | Мета, інструкція, здача; посилання ментора на дизайн Figma | `materials/uk/day-3/` |
| День 4 | Учасники | Мета, інструкція, налаштування Figma MCP, шаблони, здача | `materials/uk/day-4/`, `templates/uk/` |
| Довідник | Учасники | Шаблони (Markdown), запасні приклади `fallback/` за вказівкою ментора | `templates/uk/`, `fallback/uk/` |
| Для менторів | Менторам (прихований) | Посібник ментора, чекліст Дня 0, сценарій симуляції замовника | `mentor/uk/` |

## Шаблон розділу «День N»

| № | Елемент Moodle | Вміст |
|---|---|---|
| 1 | Підпис (Label) | Мета дня, 3–4 речення, очікуваний результат («Мета дня» з інструкції) |
| 2 | Файл | Покрокова інструкція (PDF) |
| 3 | Завдання (Assignment) | Здача: посилання на PR |
| 4 | Форум (необов'язково) | Питання по дню |

Презентацій поки немає: пункт додається, коли вони з'являться.

## Налаштування елемента «Завдання» (здача)

- **Тип здачі:** текст онлайн (одне поле для посилання на PR) і, за потреби, коментар учасника.
- **Підказка в описі:** «Вставте посилання на Pull Request у вашому репозиторії `sdd-workshop-<ім'я>` (гілка `day-N` у `main`). Репозиторій має бути **публічним** на час навчання, а PR відкритим».
- **Доступ ментора:** окремий доступ не потрібен, бо репозиторії публічні.
- **Зворотний зв'язок:** коментар ментора за рубрикою з `mentor/uk/mentor-guide.md`; рубрику учасникам не публікуємо.

## Перед публікацією

- [ ] Згенерувати PDF і переглянути кожен (діаграми Mermaid у PDF це код, а не малюнок)
- [ ] Заповнити плейсхолдери `<…>` (канал підтримки, посилання Figma, Moodle) у джерелах; перегенерувати
- [ ] Створити **курс-пісочницю**, завантажити PDF, налаштувати «Завдання», пройти як учасник на чистій машині
- [ ] Перевірити доступи (Moodle, GitHub, Figma) для зовнішніх учасників
- [ ] Залучити 1–2 нетехнічних тестових учасників і зібрати зауваження

## Прийняті рішення

- Moodle 5.2.3, додаткових плагінів немає; відстеження виконання й чекліст не використовуються.
- Правила зарахування: сторінка «Rules» на платформі.
- Репозиторії учасників публічні на час навчання.
- Відеозаписи студенти отримують окремо в Discord; у структурі Moodle їх не згадуємо.
- Курс-пісочниця потрібна.

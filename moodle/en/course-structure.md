# Course structure in Moodle

> DRAFT v2. Describes **what goes where**. Platform: Moodle 5.2.3, no extra plugins, completion tracking and checklists are not used. Enrolment rules are already on the platform ("Rules" page). Ukrainian version: [`../uk/course-structure.md`](../uk/course-structure.md). Uploading to Moodle has **not been tested** (a sandbox course is needed).

## Principles

- One section per day plus an intro section and a reference section.
- Everything needed to complete a day in one place: instruction and assignment.
- Someone who missed a session can complete the day on their own from the instruction.
- Mentor materials are **not** published to participants.
- Source of truth: Markdown in Git. PDFs are generated by `tools/build_materials.py`; do not edit them by hand in Moodle.

## How to build the files for Moodle

```bash
pip install markdown
python3 tools/build_materials.py --all --pdf        # participant version, uk and en
```
Output goes to `build/`: `day-N-instruction.uk.pdf`, `…en.pdf`, plus Day 0, setup guides, `github-mcp-setup`, `figma-mcp-setup`, `glossary`. The mentor gets a separate build with `--teacher` (do not upload it to Moodle).

## Overall structure

| Section | For whom | Contents | Source in the repository |
|---|---|---|---|
| 0. Start | Participants | About the course, schedule, support channel | text written by the curator |
| 0.1 Preparation (Day 0) | Participants | Day 0 instruction, installation guide, Cursor model tips, glossary, task "send a screenshot of `git --version` and `node -v`" | `materials/en/day-0/`, `materials/en/setup/` |
| Day 1 | Participants | Goal, instruction, submission | `materials/en/day-1/` |
| Day 2 | Participants | Goal, instruction, GitHub MCP setup (optional), submission | `materials/en/day-2/` |
| Day 3 | Participants | Goal, instruction, submission; the mentor's Figma design link | `materials/en/day-3/` |
| Day 4 | Participants | Goal, instruction, Figma MCP setup, templates, submission | `materials/en/day-4/`, `templates/en/` |
| Reference | Participants | Templates (Markdown), fallback examples `fallback/` as directed by the mentor | `templates/en/`, `fallback/en/` |
| For mentors | Mentors (hidden) | Mentor guide, Day 0 checklist, stakeholder simulation script | `mentor/en/` |

## "Day N" section template

| # | Moodle element | Contents |
|---|---|---|
| 1 | Label | Goal of the day, 3–4 sentences, expected result ("Goal of the day" from the instruction) |
| 2 | File | Step-by-step instruction (PDF) |
| 3 | Assignment | Submission: a link to the PR |
| 4 | Forum (optional) | Questions about the day |

There are no slides yet: add the item when they exist.

## "Assignment" settings (submission)

- **Submission type:** online text (one field for the PR link) and, if needed, a participant comment.
- **Hint in the description:** "Paste the link to the Pull Request in your repository `sdd-workshop-<name>` (branch `day-N` into `main`). The repository must be **public** during the course and the PR open."
- **Mentor access:** no extra access needed because the repositories are public.
- **Feedback:** a mentor comment per the rubric in `mentor/en/mentor-guide.md`; the rubric is not published to participants.

## Decisions made

- Moodle 5.2.3, no extra plugins; completion tracking and checklists are not used.
- Enrolment rules: the "Rules" page on the platform.
- Participants' repositories are public during the course.
- Students get recordings separately in Discord; they are not mentioned in the Moodle structure.
- A sandbox course is needed.
